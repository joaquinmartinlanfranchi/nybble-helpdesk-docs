Nybble AI Help Desk · Admin Guide

Quick Guide · Tenant Admin admin

How to create the organization, configure the bot, create KB users, and read the tenant's global metrics. Meant for quick reference, not for reading end to end before getting started.

The first thing to know You're the only role that can create organizations, create KB users, and configure the bot's parameters. Your metrics are always for your entire tenant — unlike an operator, who only sees their own.

Step by Step

Step 1 · Create the organization admin
  1. Use the "New Organization" form: organization name, admin email, and password.
  2. The form is valid if: the tenant name doesn't already exist, the admin email isn't already in use, and the password has at least 8 characters.
  3. After creation, the company is created inside the tenant, and the field mapping to Jira is defined as part of onboarding.

Known bug: if you fix the email but the password is still invalid, the email error stays stuck on screen even though it's already correct. LABS-532

Step 2 · Configure the bot admin
  • maxAttempts — how many failed KB search attempts force an escalation (2–5, default 3).
  • maxMessagesPerSession — cap on messages per chat session.
  • KB search confidence threshold.
  • Bot name and tone.
Step 3 · Create users and analysts admin
  1. You're the only role that can create users with the KB Manager role.
  2. If a KB Manager doesn't see the Knowledge Base section in their menu, it's because they don't have the role assigned — they'll ask you for it.
  3. You also create and manage Analysts (Agents/Operators) from Analyst Management → + New Analyst.
  4. You assign each analyst one or several companies — that determines which escalations they'll see in their Inbox. You can edit that assignment at any time, or block their access, from the same screen.
Step 4 · View the tenant's global metrics admin
  • Tickets and times by client — which company consumes the most support.
  • Tickets and times by human agent — the aggregated counterpart of each operator's "My Performance".

Neither view has a documented formula — treat them as directional, not as an audited number.

Step 5 · Review AI Observability admin
  • Settings → AI Observability: tokens, cost, quality score, KB matching efficiency, filters by date/model/feature.
  • The quality score (LLM-as-a-judge) excludes the main chat — ~85% of total traffic has no quality measurement.
  • KB matching efficiency does cover the main chat, but it measures whether retrieval found something relevant, not the quality of the final response.

Things to Keep in Mind

Known Issues During the Pilot
  • Blocking bug in organization creation: the email error stays stuck on screen even after you've fixed it, if the password is still invalid. LABS-532
  • AI Observability's quality score doesn't cover the main chat — the most-used part of the product is the one with the least quality measurement. LABS-529
  • There's no SLA framework — that's a deliberate decision, not something pending to be built. Don't promise SLAs to a client based on the dashboard.
  • Metrics by client and by agent have no documented formula.

Quick Checklist

Do This
  • Verify email and password (min. 8 characters) before submitting an organization creation
  • Use per-client/per-agent metrics as directional, not as an audited number
  • Let operators know the maxAttempts range you configured, so they understand when the bot escalates
Avoid This
  • Promising SLAs to a client based on this dashboard — that framework doesn't exist
  • Assuming AI Observability's quality score reflects the main chat
  • Resubmitting the creation form without checking email and password — the UI bug can mislead you
